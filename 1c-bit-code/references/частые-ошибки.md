# Частые ошибки в коде 1С, который пишет Claude

Собраны по проверке большого объёма кода в реальных проектах. Каждая ошибка встречалась больше чем в одном
проекте. Перед сдачей своего кода пройди по пунктам и для каждого ответь: «есть» или «нет».

1. **Логика завязана на текст.** Признак учёта в «Комментарии», ветвление по строке-представлению («Выбывает»),
   поиск или удаление по куску текста сообщения типовой, `ПОДОБНО "%…%"` для определения вида договора,
   `ВЫБРАТЬ ПЕРВЫЕ 1 … ГДЕ … ПОДОБНО`.
   → Признак хранить в реквизите, перечислении или регистре. Сравнивать со ссылкой или значением перечисления.
   Выбирать запись по точному ключу с явным `МАКСИМУМ`/`МИНИМУМ`. Пользователь может поправить текст, а у типовой
   меняются формулировки и язык интерфейса (казахский).

2. **Прочитал → проверил → записал без блокировки.** Остаток в `ПередЗаписью`, флаг «уже запущено», номера строк
   для последующей правки, статус заказа перед отправкой.
   → Всё в одной транзакции, управляемую блокировку ставить до чтения ([method/транзакции-и-блокировки.md](method/транзакции-и-блокировки.md)).
   Остатки контролировать по std661 ([method/проведение.md](method/проведение.md)). Что будет, если два пользователя
   или два задания запустят это одновременно?

3. **Транзакция не там.**
   - Нет транзакции, хотя нужна: документ пишется несколькими `Записать()` подряд, или данные правятся в нескольких
     объектах, которые должны измениться вместе.
   - Транзакция есть, хотя не нужна: вокруг одной записи объекта, вокруг заполнения объекта в памяти, внутри записи
     или проведения.

4. **Дубли, мёртвый код, «на будущее».** Одинаковые функции под разными именами, одно значение (ключ, статус),
   собранное в нескольких местах, параметры, которые никуда не передаются, функции и режимы, которые никто не
   вызывает, разовая задача, сделанная несколькими способами, ветки под кнопку, которой нет.
   → Найти неиспользуемое и удалить. Общее вычисление — одной функцией. Разовая задача — одним способом.

5. **«Вызов сервера» + привилегированный режим без проверки прав.** Такая экспортная функция доступна любому
   пользователю с клиента.
   → Не отдавать на клиент пароли и чужие данные. Если без привилегий не обойтись, проверять роль внутри функции
   или выполнять действие на сервере целиком ([method/размещение-кода.md](method/размещение-кода.md), std679, std485).
   Под Фреш привилегированный режим не работает вовсе.

6. **Молча подставляет вместо отказа.** Нет ставки НДС — подставляется пустая. Нет склада — склад по умолчанию.
   Нет объекта — создаётся на лету.
   → Если нужного нет, это ошибка с понятным текстом. Подстановку делать, только когда она входит в задачу.

7. **Ошибка в одной строке пакета ломает учёт остальных.** Обработанной помечается вся порция, хотя часть не
   обработана, или одна ошибка останавливает всю партию.
   → Признак «обработано» ставить по каждой записи после её успешной обработки. Ошибочные оставлять на повтор.

8. **Клиентское и история в коде.** В тиражный код попадают «у клиента», даты, номера задач, «прежняя загрузка»,
   настройки одного клиента, зашитые по умолчанию.
   → История — в git и документах. Тиражный код не знает про конкретного клиента.

9. **Инструкция расходится с проверенным.** В инструкцию для боевой базы попадает вариант, который не проверяли,
   а проверен был другой.
   → В инструкцию идёт только проверенное. Непроверенное помечать прямо.
