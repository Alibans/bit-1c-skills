# Транзакции и блокировки

Стандарты: std783, std648, std460, std659, std661, std490.

## Ответственное чтение (std648)
Чтение называют ответственным, если по его результату меняются данные или принимается решение, после которого данные изменятся. Такое чтение делают в транзакции, и управляемую блокировку ставят **до** чтения. Пример: прочитали счётчик, прибавили единицу, записали. Без блокировки две сессии прочитают одно и то же значение, и одно увеличение потеряется.
- Данные, которые будут записаны, блокируют исключительно, данные для решения — хотя бы разделяемо.
- Если меняется ссылочный объект, дополнительно ставят объектную блокировку (std490), см. ниже.

## Транзакция (std783)
- Исключение транзакцию **не откатывает**. Оно ставит признак ошибки, а откат происходит при `ЗафиксироватьТранзакцию`/`ОтменитьТранзакцию`. Отсюда ошибка «В этой транзакции уже происходили ошибки».
- Шаблон:
```bsl
НачатьТранзакцию();
Попытка
	// блокировка, чтение, запись
	ЗафиксироватьТранзакцию();
Исключение
	ОтменитьТранзакцию();
	// запись в журнал регистрации, ВызватьИсключение при необходимости
КонецПопытки;
```
- Начало и конец — в одном методе. Между `НачатьТранзакцию` и `Попытка` ничего не пишут. `ОтменитьТранзакцию` — первая строка в `Исключение`. `Блокировка.Заблокировать()` — внутри `Попытка`.
- Вокруг записи одного объекта транзакцию не открывают: запись уже идёт в транзакции. То же в `ПередЗаписью`, `ПриЗаписи` и `ОбработкаПроведения`.
- Пока транзакция открыта, нельзя ждать ввода пользователя и обращаться к внешним сервисам. Транзакция должна быть короткой.

## Управляемые блокировки (std460, std659)
- В конфигурации режим управления блокировками «Управляемый». `ДЛЯ ИЗМЕНЕНИЯ` в запросах в этом режиме не используется.
- Порядок блокировок регистров и объектов фиксируется один и тот же во всех местах кода. Взаимоблокировку исправляют этим порядком, а не повторными попытками и не расширением области блокировки.
- Если ищем лишние блокировки, начинаем с последовательностей, регистров накопления и бухгалтерии.

## Объектные блокировки (std490)
- **Пессимистическая** (`ЗаблокироватьДанныеДляРедактирования`, `Объект.Заблокировать()`) **добровольная**: она не мешает записи, а мешает только поставить ещё одну блокировку. Объект защищён, только если каждый путь, который его меняет, сначала берёт блокировку. Поэтому перед изменением существующего объекта из кода блокировку ставим.
- Блокировку с ид формы и без него для одного объекта не смешивают: будет исключение.
- Неудачную объектную блокировку внутри транзакции можно перехватить в `Попытка` **без отката** транзакции. Это исключение из общего правила.
- Два шаблона по std490. В интерактивной работе ошибка блокировки показывается пользователю: кто держит объект. В фоновом и регламентном задании объект пропускаем, пишем предупреждение в журнал и обрабатываем в следующий запуск.
- **Оптимистическая** блокировка (версия объекта) срабатывает сама: она не даёт записать объект, если его изменили после чтения. Пользователю вместо сырой ошибки платформы сообщают, что объект изменён другим пользователем и что сделать (перечитать).
