# Обработчики событий объекта

Стандарты: std396, std463, std464, std465, std466, std752, std686, std773, std455.

## Какой обработчик что делает
- **`ОбработкаЗаполнения(ДанныеЗаполнения, ТекстЗаполнения, СтандартнаяОбработка)`** заполняет новый объект по `ДанныеЗаполнения` с развилкой по типу. Здесь же отказывают во вводе на основании, например когда основание — группа или непроведённый документ. Отказывают через `ВызватьИсключение` с понятным текстом (std396).
- **`ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты)`** нужна для проверок, которые не покрывает свойство «Проверка заполнения»: значение зависит от других реквизитов, обязательность зависит от условия (std463).
- **`ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)`** заполняет вычисляемые реквизиты и проверяет состояние. Только здесь доступны **старые** значения в базе (std464).
- **`ПриЗаписи(Отказ)`** записывает связанные данные в другие объекты. Сам записываемый объект здесь не меняют: он уже в базе (std465).
- **`ПриКопировании(ОбъектКопирования)`** очищает реквизиты, которые не должны попасть в копию (std466).
- **`ПередУдалением(Отказ)`** выполняет то, что нужно сделать до удаления (std752).
- Проведение описано в [проведение.md](проведение.md).

## `ОбменДанными.Загрузка` — первой строкой (std773)
В `ПередЗаписью`, `ПриЗаписи` и `ПередУдалением` первой строкой проверяем `Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;`. При обмене объект должен записаться как есть: без повторной бизнес-логики и без проверок.
- То же правило действует для **подписок на события** на эти же события.
- `ОбменДанными.Загрузка = Истина` не используют, чтобы отключить проверки в своём коде. Код, который его ставит, сам отвечает за то, что объект заполнен правильно.
- Любое исключение из правила сопровождается комментарием с причиной.

## `Отказ` — только `= Истина` (std686)
- Не писать `Отказ = Ложь` и `Отказ = Функция()`: это сбросит `Истина`, которую поставил предыдущий код или подписка. Правильно: `Если ЕстьОшибки Тогда Отказ = Истина; КонецЕсли;` или `Отказ = Отказ Или ЕстьОшибки;`.
- То же касается `СтандартнаяОбработка`.
- Вместе с `Отказ = Истина` пользователю сообщают причину. Иначе он увидит только «не удалось записать».

## Условная обязательность — одной формой (std463)
Создать массив `НепроверяемыеРеквизиты`, добавить в него то, что сейчас проверять не нужно, и в конце удалить эти имена из `ПроверяемыеРеквизиты` (процедура есть в std463). Обратная схема (добавлять в `ПроверяемыеРеквизиты`) и свои схемы не используются: тогда свойство «Проверка заполнения» перестаёт показывать, что объект на самом деле требует.

## Где лежат обработчики
- Обработчики событий — в области `ОбработчикиСобытий`, всё остальное — вне её (std455).
- Подписку на событие из модуля объекта не видно. Прежде чем менять запись или удаление объекта, нужно найти подписки на эти события (поиск по `EventSubscription` в выгрузке).
