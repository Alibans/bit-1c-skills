# Проведение документа

Стандарты: std603, std450, std477, std661, std663, std664, std689 п.1.7.

## Проводить ли документ (std603)
- Документ, который отражает событие в учёте, проводится. Непроведённый документ — черновик: он может быть неполным, проверки бизнес-логики к нему не применяются, в учёт он не попадает.
- Этапы работы с документом (согласован, отгружен) — это статусы проведённого документа. Отключать проведение ради них нельзя.
- Не проводятся документы, которые только фиксируют факт: входящее письмо, звонок, встреча.

## Как устроено
- Движения — это наборы записей регистров, где регистратор — документ. Код пишется в `ОбработкаПроведения(Отказ, РежимПроведения)` и при необходимости в `ОбработкаУдаленияПроведения`. Оба обработчика уже выполняются внутри транзакции, поэтому свою транзакцию в них не открывают.
- Регистр должен быть в списке «Движения» документа, иначе это ошибка метаданных, а не кода.
- Если удаление движений отключено (`AutoDeleteOff`), удалять их должен обработчик отмены проведения. Пустой обработчик оставит старые движения.
- **Оперативное или неоперативное проведение** выбирает платформа: дата документа совпадает с датой сеанса — оперативное, более ранняя — неоперативное. Проверять наличие (минусовые остатки, лимиты, резервы) имеет смысл только при оперативном. При неоперативном (ввод задним числом, загрузка остатков) такая проверка в основном даёт ложные отказы.
- Порядок документов внутри одной секунды определяет «момент времени» (дата + ссылка). Он **не совпадает** с порядком ввода.

## Код проведения
- Платформа сама записывает движения после выхода из обработчика, поэтому `Записать()` у наборов в проведении не вызывают (std450, АПК:105). Исключение — контроль остатков, см. ниже.
- Табличную часть читаем **одним запросом**, без цикла по строкам с обращением к реквизитам через точку. Шапку (дата, склад, контрагент) берём из объекта в памяти.
- Если запросов несколько, у них один `МенеджерВременныхТаблиц`: табличная часть помещается во временную таблицу один раз.
- В регистр не пишут то, что потом придётся получать у регистратора через точку. Регистр должен быть самодостаточным (std477).

## Контроль остатков — только если остаток может уйти в минус (std661)
1. Сначала решить, где контроль вообще нужен. Приходный документ остатки только увеличивает, ему контроль не нужен.
2. Регистры без контроля записать явно в начале, `БлокироватьДляИзменения = Ложь`, всегда в одном порядке (например, по алфавиту).
3. Регистры с контролем записать явно **в самом конце**, `БлокироватьДляИзменения = Истина`. Запись сама ставит блокировку, отдельная `БлокировкаДанных` не нужна.
4. **После этого** выполнить запрос на минусовые остатки. Если результат пустой — всё в порядке; если есть минус — `Отказ = Истина` и сообщение пользователю.

Проверять остатки в `ПередЗаписью` модуля набора записей — частая ошибка: порядок записи регистров выбирает платформа, и блокировка будет держаться всё проведение.

## Права (std689 п.1.7)
Документу, который проводится, ставят «Привилегированный режим при проведении» и «…при отмене проведения». Тогда права настраиваются на документ, а не на каждый регистр.

## Стоп
- Не добавлять контроль остатков в неоперативное проведение без названной причины.
- Не менять «Проведение», «Оперативное проведение», «Удаление движений» и список регистров без проверки движений уже проведённых документов.
