# Регистры

Стандарты: std477, std657, std733, std663, std664, std661, std708, std447, std792, std689 п.1.7.

## Какой регистр
- **Регистр сведений** хранит состояние по ключу: цены, курсы, настройки, связи. Периодический — если нужна история по датам.
- **Регистр накопления остатков** — то, что приходит и уходит. Из него получают остатки, обороты и остатки с оборотами.
- **Регистр накопления оборотов** — только обороты, остаток у него не имеет смысла.
- **Регистр бухгалтерии** — проводки по плану счетов. **Регистр расчёта** — начисления с периодом действия.
- Регистры делят по предмету учёта, а не по удобству. Количество на складе, себестоимость и аналитика продаж — три разных регистра, даже если их пишет один документ.

## Измерения, ресурсы, реквизиты
- Измерение — это ключ, ресурс — то, что суммируется, реквизит — сопутствующая информация, которая не ключ и не суммируется. Ошибку в выборе потом исправлять дороже всего, потому что меняется хранимая таблица.
- **В регистре остатков** значение может быть измерением, только если оно имеет смысл и в приходе, и в расходе. Поставщик есть в поступлении, но его нет в списании. Такое значение кладут в регистр оборотов или в реквизит, иначе остатки никогда не обнулятся.
- Для измерений, которые всегда заполнены, ставим «Запрет незаполненных значений».
- «Ведущее» измерение означает, что записи удаляются вместе со значением. Это решение по смыслу данных, а не флаг по привычке.
- Логику и отчёты по регистру не строят на реквизитах регистратора через точку (std477, АПК:123).

## Разделение итогов — компромисс, а не настройка по умолчанию
- Включают, когда много сессий одновременно пишут одинаковые комбинации измерений (std664).
- При этом медленнее чтение текущих остатков: самый быстрый план получается только без разделения итогов (std733).
- Если контроль остатков стоит в начале транзакции, разделение ничего не даёт (std661).

## Чтение
- Отборы задают в параметрах виртуальной таблицы, а не во внешнем `ГДЕ` (std657).
- Регистр сведений читают запросом, если ничего не меняется (std447).
- `МенеджерЗаписи` используют только когда отбор идёт по **всем** измерениям. Иначе — `НаборЗаписей`.
- Итоги среза последних или первых для периодического регистра сведений включают, только если выполнены все условия std708: большой объём, частые срезы на текущий момент и т.д.

## Запись больших объёмов (std792)
- Наборы записей не пишут в цикле по одной-несколько записей. Пишут порциями примерно по 1000.
- Большой набор, где меняется не больше 30% записей, целиком не перезаписывают, а записывают только изменения.

## Права
Роль не даёт права изменять регистры, подчинённые регистратору: их записи принадлежат проведению (АПК:229). В командный интерфейс такие регистры не выводят.
